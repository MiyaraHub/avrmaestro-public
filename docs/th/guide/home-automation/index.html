Home Assistant และ Hubitat: ฉากของคุณ ทำงานได้ โดยไม่ต้องใช้โทรศัพท์

เชื่อมโยง AVR Maestro กับ Home Assistant หรือ Hubitat แล้วทุกฉากที่คุณสร้างไว้จะกลายเป็นสคริปต์ต้นฉบับบนฮับของคุณ จากนั้นฮับจะสื่อสารกับเครื่องรับโดยตรงในเครือข่ายของคุณเอง ดังนั้นคำสั่ง “Alexa, movie night” จึงใช้ได้แม้โทรศัพท์ปิดอยู่ พักหน้าจอ หรืออยู่คนละประเทศ

ทำไมจึงทำงานได้โดยไม่ต้องใช้แอป

อินทิเกรชันส่วนใหญ่ให้โทรศัพท์เป็นคนกลาง คือโทรศัพท์ได้ยินคำสั่ง โทรศัพท์ส่งคำสั่ง และระบบอัตโนมัติทำงานได้เฉพาะตอนที่โทรศัพท์ตื่นอยู่และอยู่ในเครือข่าย

AVR Maestro ไม่ทำแบบนั้น แอปคอมไพล์ฉากของคุณเป็นสคริปต์ที่อยู่บนฮับ แล้วฮับส่งคำสั่งไปยัง IP ภายในเครือข่ายของเครื่องรับ หน้าที่ของแอปจบลงเมื่อการซิงค์เสร็จ

  • ทำงานในเครือข่ายภายในเป็นหลัก: ไม่มีอะไรผ่านเซิร์ฟเวอร์ของ MiyaraHub ฮับกับเครื่องรับของคุณคุยกันเอง
  • ไม่ขึ้นกับโทรศัพท์: เมื่อเผยแพร่ฉากแล้ว ฉากจะทำงานไม่ว่าจะติดตั้งแอปไว้บนโทรศัพท์ที่สร้างฉากนั้นหรือไม่
  • ผู้ช่วยของคุณ ไม่ใช่ของเรา: Alexa, Google Assistant และ Siri Shortcuts เข้าถึงสคริปต์เหล่านี้ผ่านฮับที่คุณไว้ใจอยู่แล้ว AVR Maestro ไม่เพิ่มระบบเสียงของตัวเอง

Home Assistant ตั้งแต่ต้นจนจบ

  • 1. เพิ่มเครื่องรับของคุณใน Home Assistant ก่อน การตั้งค่า › อุปกรณ์ & บริการ › เพิ่มการผสานรวม › Denon AVR (หรือ HEOS) จากนั้นระบุ IP ภายในเครือข่ายของเครื่องรับ Home Assistant จะสร้างเอนทิตีเครื่องเล่นสื่อให้เครื่องรับนั้น
  • 2. เปิด Settings › Home Automation ใน AVR Maestro แล้วแตะการ์ด Home Assistant
  • 3. ป้อนที่อยู่ Home Assistant ของคุณ ซึ่งเป็นที่อยู่ภายในเครือข่าย เช่น http://192.168.1.150:8123 หรือ URL ภายนอกของ Nabu Casa
  • 4. เข้าสู่ระบบและให้สิทธิ์ เบราว์เซอร์ที่ปลอดภัยภายในแอปจะเปิดหน้าเข้าสู่ระบบของ Home Assistant เอง ข้อมูลรับรองของคุณไปที่ Home Assistant ไม่เคยมาถึงเรา
  • 5. แอปหาเครื่องรับของคุณเอง แอปสแกนเอนทิตีเครื่องเล่นสื่อของคุณและให้คะแนนตามรุ่น ชื่อ และความสามารถด้านเซอร์ราวด์ แล้วกรอกเอนทิตีที่ถูกต้องให้คุณ
  • 6. ซิงค์ ฉากของคุณจะถูกสร้างเป็นสคริปต์และอัปโหลด หลังจากนั้นเมื่อแก้ไขฉาก สคริปต์จะอัปเดตเองเบื้องหลัง ไม่มีปุ่มให้ต้องจำ
เมื่อซิงค์แล้ว

สร้างแดชบอร์ดที่น่ามอง

ตอนนี้ Home Assistant มีตัวควบคุมสำหรับทุกอย่างที่สั่งเครื่องรับของคุณได้ แต่ไม่มีความเห็นเลยว่าจะจัดวางอย่างไร ตัวอย่างแดชบอร์ด คือการจัดวางแบบหนึ่งพร้อม YAML ฉบับเต็ม ได้แก่ ไทล์แหล่งสัญญาณและเซอร์ราวด์ที่สว่างเมื่อเป็นตัวที่ใช้งานอยู่ ระดับเสียงเป็น dB จริง ฉากของคุณที่อ่านชื่อของตัวเอง และแผนที่ตามจริงว่า Home Assistant มองเห็นและมองไม่เห็นอะไร

ไม่ใช่แค่ฉาก

พรีเซ็ตลำโพง Dirac และ Audyssey ด้วย

เปิด ซิงค์การควบคุมขั้นสูง แล้วแอปจะเผยแพร่สคริปต์มากกว่าแค่ฉากของคุณ ได้แก่ พรีเซ็ตลำโพงทุกชุด ช่องฟิลเตอร์ Dirac Live ทุกช่อง และเส้นโค้ง Audyssey ทุกเส้น การซิงค์เต็มรูปแบบบน Cinema 30 ได้สคริปต์กว่าเจ็ดสิบตัว ปุ่มบนแดชบอร์ดหรือคำสั่งเสียงจึงโหลดฟิลเตอร์ Dirac หรือสลับเส้นโค้งห้องได้เหมือนเรียกฉาก

อ่านได้ ไม่ใช่แค่เขียน

Home Assistant มองเห็นว่าอะไรกำลังใช้งานอยู่

สคริปต์สั่งให้ทำงานได้แต่อ่านค่าไม่ได้ แดชบอร์ดยุคแรกจึงสลับเส้นโค้ง Audyssey หรือช่อง Dirac ได้ แต่ไม่มีทางแสดงว่าตัวไหนเปิดอยู่ ตอนนี้ค่าที่แอปมีอยู่แล้ว ได้แก่ โหมดเซอร์ราวด์สด ฟิลเตอร์ Dirac ที่ใช้งาน พรีเซ็ตลำโพง ตัวหรี่ไฟ และอีกหลายสิบรายการ ถูกเผยแพร่เป็นแอตทริบิวต์บนเซนเซอร์สถานะของเครื่องรับ ไทล์จึงสว่างตามการตั้งค่าที่ทำงานอยู่จริง

ทุกห้อง

โซนอื่นของคุณ จากแดชบอร์ดเดียวกัน

การเปิดปิด ระดับเสียง และการปิดเสียงของโซน 2 และโซน 3 เผยแพร่เป็นสคริปต์ของตัวเอง ระเบียงหรือห้องที่สองจึงตอบสนองต่อแดชบอร์ดหรือผู้ช่วยเสียงได้เหมือนที่โซนหลักทำมาตลอด ปุ่มจะมีเฉพาะโซนที่เครื่องรับของคุณรายงานจริง เครื่องรับสองโซนจึงไม่มีวันมีโซน 3 งอกขึ้นมา

ถ้าคุณซิงค์ด้วยบิลด์รุ่นเก่า

ID สคริปต์ของคุณเปลี่ยนครั้งเดียว

สคริปต์เคยตั้งชื่อตามฉากและเครื่องรับ ดังนั้นการเปลี่ยนชื่ออย่างใดอย่างหนึ่งจึงทิ้งสคริปต์เก่าไว้และสร้างตัวที่สองขึ้นมาเงียบๆ ตอนนี้ตั้งชื่อตามฉากและที่อยู่ MAC ของเครื่องรับ ซึ่งทำให้การเปลี่ยนชื่ออัปเดตสคริปต์เดิมแทนที่จะสร้างซ้ำ

การซิงค์ครั้งแรกหลังการเปลี่ยนแปลงนั้นจะแทนที่สคริปต์เก่าด้วยสคริปต์ใหม่ สิ่งที่คุณสร้างบน ID เก่าต้องชี้ใหม่หนึ่งครั้ง เช่น ปุ่มบนแดชบอร์ด ระบบอัตโนมัติ หรือชื่อเรียกสำหรับเสียง เปิดสคริปต์ใน Home Assistant เพื่อดู Entity ID ใหม่ของมัน

เอนทิตีตอนนี้อ่านจากเครื่องรับด้วย คือ cinema30 แทนที่จะเป็นรหัสเครื่องสามสิบสองตัวอักษร รายการจึงอ่านรู้เรื่องและระบบเติมข้อความอัตโนมัติหาเจอ ID จากเวอร์ชันก่อนหน้ายังใช้งานได้

Hubitat

รองรับ Hubitat ผ่าน Maker API และมีป้าย BETA ในแอปเพราะใหม่กว่าเส้นทาง Home Assistant ไม่ใช่เพราะยังไม่เสร็จ

  • Hub IP คือที่อยู่ของ Hubitat ของคุณใน LAN
  • Maker API App ID คือตัวเลขใน URL ของแอป Maker API เอง
  • Access Token ออกโดย Maker API เมื่อคุณเปิดใช้งาน

เปิดใช้ Maker API บนฮับก่อน (Apps › Add Built-In App › Maker API) แล้วจะได้ครบทั้งสามค่า วางลงไป AVR Maestro จะค้นหาเครื่องรับของคุณ เผยแพร่ฉากเป็นลำดับคำสั่ง และส่งสถานะสดกลับมา แดชบอร์ด Hubitat จึงสะท้อนสิ่งที่เครื่องรับกำลังทำอยู่จริง ไม่ใช่สิ่งที่ถูกสั่งครั้งล่าสุด

Webhooks

Home Assistant และ Hubitat ส่งคำสั่งไปยังเครื่องรับ ส่วน Webhook ไปทางตรงข้าม คือเมื่อเครื่องรับทำอะไรสักอย่าง ก็แจ้งสิ่งอื่นๆ ให้รู้ เปิดเครื่องรับแล้ว AVR Maestro จะโพสต์ข้อความเล็กๆ ไปยังที่อยู่ที่คุณเลือก ข้อความนั้นคือ webhook

นี่คือส่วนเดียวที่ไม่ได้เป็นอิสระจากโทรศัพท์ ฉากที่ซิงค์ของคุณกลายเป็นสคริปต์บนฮับและทำงานได้ไม่ว่าแอปจะอยู่ใกล้หรือไม่ Webhook ต่างออกไป เพราะ AVR Maestro คือผู้เฝ้าดูเครื่องรับ ทริกเกอร์จึงทำงานตอนที่แอปเปิดอยู่บนอุปกรณ์ที่มองเห็นเครื่องรับ หากต้องการให้บางอย่างทำงานโดยไม่มีอะไรรันอยู่ ให้สร้างบนฮับของคุณรอบเอนทิตีเครื่องรับแทน

ทริกเกอร์ทั้งสี่

เหตุการณ์ทริกเกอร์ทำงานเมื่อจำกัดให้แคบลงได้เป็น
เปิดเครื่องรับเครื่องรับออกจากโหมดสแตนด์บาย-
ปิดเครื่องรับเครื่องรับเข้าสู่โหมดสแตนด์บาย-
เปลี่ยนอินพุตที่ใช้งานอยู่แหล่งสัญญาณที่เลือกเปลี่ยนไปหนึ่งอินพุต ในช่อง Only trigger for input source
เรียกใช้ฉากมีการใช้ฉากหนึ่งฉาก ในช่อง Select Scene

การจำกัดให้แคบลงคือสิ่งที่ทำให้ทริกเกอร์มีประโยชน์ แทนที่จะแค่ส่งเสียงรบกวน “เปลี่ยนอินพุตที่ใช้งานอยู่” กับทุกอินพุตเป็นน้ำท่วมทะลัก แต่ทริกเกอร์เดียวกันที่ปักไว้กับอินพุตที่โปรเจกเตอร์ของคุณต่ออยู่เพียงอินพุตเดียวคือสวิตช์ไฟ

รายการอินพุตคือรายการที่เครื่องรับของคุณเองรายงาน จึงสะท้อนแหล่งสัญญาณที่คุณเปลี่ยนชื่อหรือซ่อนไว้อยู่แล้ว ส่วนรายการฉากคือฉากของคุณเอง

ตั้งค่าทีละขั้นตอน

นี่คือเส้นทาง Home Assistant ซึ่งเป็นเส้นทางที่คนส่วนใหญ่ต้องการ ทำฝั่ง Home Assistant ก่อน เพราะแอปต้องมีปลายทางให้ชี้ไป

ใน Home Assistant

  • 1. Settings › Automations & Scenes › Create Automation › Create new automation
  • 2. Add Trigger › Webhook Home Assistant จะสร้าง Webhook ID แบบสุ่มยาวๆ ให้คุณ
  • 3. แทนที่ด้วยชื่อที่คุณจำได้ เช่น avr-power-on, avr-movie-night ชื่ออะไรก็ได้ ขอเพียงไม่ซ้ำกันบน Home Assistant ของคุณ จดไว้ เพราะคุณต้องพิมพ์ชื่อเดียวกันใน AVR Maestro
  • 4. ในการตั้งค่าของ webhook ให้อนุญาต POST นั่นคือสิ่งที่ AVR Maestro ส่ง ตั้งเป็น Local-only ก็ได้ เพราะแอปอยู่ในเครือข่ายของคุณเอง
  • 5. เพิ่มสิ่งที่ต้องการให้ทำ เช่น หรี่ไฟ ปิดม่าน หรือเริ่มฉาก แล้วบันทึกระบบอัตโนมัติ

ใน AVR Maestro

  • 1. Settings › Home Automation › Webhooks แล้วแตะ เพิ่มทริกเกอร์แรก หรือปุ่ม + เมื่อมีทริกเกอร์อยู่แล้ว
  • 2. เหตุการณ์ทริกเกอร์ เลือกสิ่งที่ควรทำให้ทริกเกอร์ทำงาน หากเลือก เปลี่ยนอินพุตที่ใช้งานอยู่ หรือ เรียกใช้ฉาก จะมีช่องที่สองเพิ่มขึ้นมาเพื่อจำกัดให้แคบลง
  • 3. จะส่งไปที่ใด ปล่อยไว้ที่ Home Assistant แอปรู้ที่อยู่อยู่แล้ว เพราะคุณเชื่อมโยงไว้ก่อนหน้าแล้วในหน้าจอเดียวกันนี้
  • 4. Webhook ID พิมพ์ ID เดียวกับที่ใช้ใน Home Assistant ไม่ต้องให้อย่างอื่นตรงกัน ด้านล่างแอปจะแสดงที่อยู่เต็มที่จะโพสต์ไป คือ Sends to http://your-ha:8123/api/webhook/avr-power-on เพื่อให้ตรวจสอบได้ก่อนบันทึก
  • 5. บันทึก จากนั้นกด ทดสอบ ที่ทริกเกอร์ในรายการ ระบบอัตโนมัติ Home Assistant ของคุณควรทำงานทันที
คุณไม่ต้องพิมพ์ URL เลยสำหรับเส้นทาง Home Assistant แอปสร้างให้จาก Home Assistant ที่คุณเชื่อมโยงไว้ และค้นหาที่อยู่นั้นทุกครั้งที่ทริกเกอร์ทำงาน ถ้าย้าย Home Assistant ไปพอร์ตใหม่ ชื่อโฮสต์ใหม่ หรือที่อยู่ Nabu Casa ทุก webhook ที่คุณสร้างไว้แล้วจะตามไปเอง ไม่ต้องซิงค์ใหม่และไม่มีปุ่มให้กด
ถ้าแผ่นขึ้นว่า ยังไม่ได้เชื่อมโยง Home Assistant ให้ทำการ์ด Home Assistant ที่ด้านบนของหน้านี้ก่อน เส้นทาง webhook ต้องมีที่อยู่ให้สร้างต่อ

ส่งไปที่อื่นที่ไม่ใช่ Home Assistant

สลับ จะส่งไปที่ใด เป็น Other แล้ววาง URL เต็มลงใน Webhook URL อะไรก็ตามที่รับ POST ได้ใช้ได้หมด เช่น โฟลว์ Node-RED แอปเพล็ต IFTTT สคริปต์บน NAS หรือปลายทาง Hubitat Maker API เส้นทางนี้เก็บที่อยู่ตามที่คุณพิมพ์เป๊ะๆ ถ้าปลายทางย้าย คุณต้องแก้ทริกเกอร์

เนื้อหา JSON เล็กๆ การ์ด สิ่งที่จะส่ง ในหน้าจอเดียวกันอธิบายด้วยภาษาธรรมดาสำหรับทริกเกอร์ที่คุณเลือก คุณจึงไม่ต้องเดา และนี่คือชื่อฟิลด์ที่ระบบอัตโนมัติของคุณอ่าน:

ทริกเกอร์ฟิลด์ในข้อความ
เปิด / ปิดเครื่องรับevent, timestamp
เปลี่ยนอินพุตที่ใช้งานอยู่...และ source
เรียกใช้ฉาก...และ sceneId กับ sceneName

ในระบบอัตโนมัติของ Home Assistant ค่าเหล่านั้นมาเป็น {{ trigger.json.event }}, {{ trigger.json.source }} และอื่นๆ คุณจะอ่านค่าเหล่านั้นหรือไม่สนใจเลยแล้วทำงานตามข้อเท็จจริงว่ามันทำงานแล้วก็ได้ คนส่วนใหญ่เลือกอย่างหลัง

ถ้าต้องการรูปแบบอื่น เช่น บริการที่ต้องการฟอร์แมตของตัวเอง ให้เปิด Send my own JSON instead ใต้การ์ดนั้นแล้วเขียนที่นั่น ส่วนนี้ถูกพับเก็บและติดป้ายขั้นสูง เพราะแทบไม่มีใครต้องใช้ ไม่ใช่เพราะไม่แนะนำ

หน้าจอนี้ชื่อ Webhooks เพราะมันคือสิ่งนั้น ถ้าคุณกำลังหาระบบอัตโนมัติที่ทำงานบนฮับของคุณ นั่นคือการ์ด Home Assistant และ Hubitat ด้านบน ฉากที่ซิงค์จะกลายเป็นสคริปต์ที่นั่น ไม่ใช่ webhook ที่นี่

เมื่อ webhook ไม่มาถึง

เรียงตามลำดับที่ควรตรวจสอบ เพราะสองข้อแรกมักเป็นสาเหตุเกือบทุกครั้ง:

  • กดทดสอบก่อน มันส่งข้อความเดียวกับที่ทริกเกอร์จริงส่ง ไปยังที่อยู่เดียวกัน และบอกว่าเกิดอะไรขึ้นในสามอย่าง คือ ส่งถึงแล้ว ส่งไม่ถึง หรือข้ามไปเพราะสวิตช์ของทริกเกอร์ปิดอยู่ ถ้าทดสอบส่งถึงแต่เหตุการณ์จริงไม่ถึง ปัญหาอยู่ที่ทริกเกอร์ ส่วนใหญ่คือ เปลี่ยนอินพุตที่ใช้งานอยู่ ที่จำกัดไว้กับอินพุตที่คุณไม่ได้สลับไปใช้จริง
  • ตรวจสอบว่า ID ตรงกันเป๊ะ Webhook ID ของ Home Assistant แยกตัวพิมพ์ใหญ่เล็ก และไม่ยอมให้มีช่องว่างเกินมา แอปพิมพ์ที่อยู่เต็มที่จะโพสต์ไปไว้ใต้ช่อง ให้เทียบกับที่อยู่ในระบบอัตโนมัติของคุณ
  • ตรวจสอบว่าระบบอัตโนมัติอนุญาต POST ทริกเกอร์ webhook ของ Home Assistant ที่อนุญาตเฉพาะ GET จะเมินสิ่งที่ AVR Maestro ส่งไปเงียบๆ
  • ตรวจสอบว่าสวิตช์ของทริกเกอร์เปิดอยู่ แต่ละทริกเกอร์มีปุ่มสลับของตัวเองในรายการ และทริกเกอร์ที่ปิดอยู่จะถูกข้ามไป ไม่ใช่ล้มเหลว
  • ทริกเกอร์เป็นของเครื่องรับเครื่องเดียว รายการที่คุณกำลังดูคือรายการของเครื่องรับที่เลือกอยู่ตอนนี้ เครื่องรับอีกเครื่องมีรายการของตัวเอง กฎที่สร้างที่นี่จึงไม่ทำงานกับห้องอื่น
  • แอปต้องคอยเฝ้าดูอยู่ AVR Maestro คือสิ่งที่สังเกตเห็นว่าเครื่องรับเปลี่ยน ดังนั้นจะไม่มีอะไรทำงานจากโทรศัพท์ในกระเป๋าที่ปิดแอปไว้ นั่นคือข้อแลกเปลี่ยนที่อธิบายไว้ตอนต้นของส่วนนี้ ไม่ใช่ข้อบกพร่อง
  • Webhook เป็นส่วนหนึ่งของระบบบ้านอัตโนมัติ หากไม่ปลดล็อก ทริกเกอร์จะมองเห็นได้แต่ไม่มีอะไรถูกส่ง และการทดสอบจะบอกตรงๆ แทนที่จะแสร้งว่าสำเร็จ
