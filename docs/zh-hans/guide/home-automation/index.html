Home Assistant · Hubitat · Webhook

Home Assistant 与 Hubitat：你的场景，无需手机即可运行

将 AVR Maestro 关联到 Home Assistant 或 Hubitat，你创建的每个场景都会成为中枢上的原生脚本。此后，中枢直接通过你自己的网络与接收机通信，所以“Alexa，观影之夜”在你的手机关机、休眠，甚至身在另一个国家时依然有效。

为什么无需应用也能运行

大多数集成都让手机充当中间人：手机听到指令，手机发送指令，自动化只有在手机处于唤醒状态并联网时才能工作。

AVR Maestro 不这样做。它会把你的场景编译成存放在中枢上的脚本，由中枢向接收机的本地 IP 发送指令。同步完成后，应用的任务就结束了。

  • 本地优先：任何内容都不会经过 MiyaraHub 的服务器。你的中枢和接收机直接相互通信。
  • 不依赖手机：场景一旦发布，无论创建它的手机上是否还装着应用，它都会运行。
  • 用你的助手，而不是我们的：Alexa、Google Assistant 和 Siri 快捷指令都通过你信任的中枢访问这些脚本。AVR Maestro 不会添加自己的语音层。

Home Assistant 全流程

  • 1. 请先将您的接收机添加到 Home Assistant。 设置 › 设备 & 服务 › 添加集成 › Denon AVR（或 HEOS），然后输入接收机的本地 IP。Home Assistant 会为其创建一个媒体播放器实体。
  • 2. 在 AVR Maestro 中打开设置 › 家庭自动化，然后点按 Home Assistant 卡片。
  • 3. 输入你的 Home Assistant 地址：可以是形如 http://192.168.1.150:8123 的本地地址，也可以是你的外部 Nabu Casa URL。
  • 4. 登录并授权。应用会打开一个安全的内置浏览器，显示 Home Assistant 自己的登录页。你的凭据只会发给 Home Assistant，绝不会发给我们。
  • 5. 它会自动找到你的接收机。应用会扫描你的媒体播放器实体，并按型号、名称和环绕声能力打分，然后为你填入正确的实体。
  • 6. 同步。你的场景会被构建为脚本并上传。此后，编辑场景会在后台更新其脚本，不需要记得去点任何按钮。
同步完成之后

打造一个值得一看的仪表盘

Home Assistant 现在为接收机能接受的每项指令都提供了一个控制项，但对如何排列它们毫无主张。仪表盘示例就是其中一种排列，并附有完整的 YAML：当前生效时会点亮的输入源和环绕声磁贴、以真实 dB 显示的音量、读取自己名称的场景，以及一份如实说明 Home Assistant 能看到什么、看不到什么的清单。

不只是场景

扬声器预设、Dirac 和 Audyssey 也一样

开启同步高级控制后，应用发布的脚本远不止场景：每个扬声器预设、每个 Dirac Live 滤波器插槽、每条 Audyssey 曲线都会发布。在 Cinema 30 上完整同步会生成七十多个脚本，因此仪表盘按钮或语音指令可以像调用场景一样加载 Dirac 滤波器或切换房间曲线。

不只写入，还能读取

Home Assistant 能看到当前生效的是什么

脚本只能运行，不能读取，所以早期的仪表盘可以切换 Audyssey 曲线或 Dirac 插槽，却无法显示当前是哪一个。应用已掌握的读数，包括实时环绕声模式、当前的 Dirac 滤波器、扬声器预设、调光以及另外几十项，现在都会作为属性发布到接收机的状态传感器上，因此磁贴可以为真正在运行的设置点亮。

每个房间

同一个仪表盘控制你的其他分区

分区 2 和分区 3 的电源、音量和静音会发布为各自独立的脚本，因此露台或另一个房间也能像主分区一样响应仪表盘或语音助手。只有接收机实际报告的分区才会有按钮，所以双分区的接收机不会凭空多出一个分区 3。

如果你用旧版本同步过

你的脚本 ID 会变一次

脚本过去以场景和接收机来命名，因此重命名其中任何一个，都会留下旧脚本并悄悄创建出第二个。现在它们以场景和接收机的 MAC 地址命名，正是这一点让重命名能更新原有脚本，而不是另起一个。

这次变更之后的首次同步会用新脚本替换旧脚本。凡是基于旧 ID 搭建的内容，都需要重新指向一次，例如仪表盘按钮、自动化和语音别名。请在 Home Assistant 中打开该脚本，查看它的新实体 ID。

实体现在也以接收机命名，形如 cinema30，而不再是三十二个字符的机器标识符，所以列表清晰易读，自动补全也能找到它们。早期版本的 ID 仍可继续使用。

Hubitat

Hubitat 通过其 Maker API 获得支持，在应用中标记为 BETA，是因为它比 Home Assistant 方案更新，而不是因为尚未完成。

  • 集线器 IP：你的 Hubitat 在局域网中的地址。
  • Maker API 应用 ID：Maker API 应用自身 URL 中的数字。
  • 访问令牌：启用 Maker API 时由其颁发。

请先在中枢上启用 Maker API（应用 › 添加内置应用 › Maker API），它会给你这三项信息。粘贴进来后，AVR Maestro 会发现你的接收机，把你的场景发布为命令序列，并回传实时状态，这样 Hubitat 仪表盘反映的就是接收机实际正在做的事，而不是它上一次被告知的内容。

Webhook

Home Assistant 和 Hubitat 是把指令发给接收机。Webhook 则反方向工作：接收机一有动作，就通知其他任何东西。打开接收机，AVR Maestro 就会向你选定的地址发送一条小消息，这条消息就是 Webhook。

这是唯一不独立于手机的部分。你同步的场景会变成中枢上的脚本，无论应用在不在附近都能运行。Webhook 则不同：监视接收机的是 AVR Maestro，所以触发器只会在应用于一台能连到接收机的设备上打开时才会触发。如果你希望在没有任何应用运行时也能触发，请围绕接收机实体在中枢上搭建。

四种触发器

触发事件触发时机可限定为
接收机开机接收机退出待机-
接收机关机接收机进入待机-
输入源变更所选输入源发生变化单个输入源，位于仅针对此输入源触发下
场景已调用某个场景被应用单个场景，位于选择场景下

限定条件才能让它们有用而不是吵闹。对每个输入源都启用“输入源变更”就像消防水龙头；而把同一个触发器限定在投影仪所接的那一个输入源上，它就是一个电灯开关。

输入源列表就是你自己的接收机所报告的那一份，因此已经反映了你重命名或隐藏过的输入源。场景列表则是你自己的场景。

逐步设置

这是 Home Assistant 方案，也是大多数人想要的。请先完成 Home Assistant 这一半，应用需要有个目标可以指向。

在 Home Assistant 中

  • 1. 设置 › 自动化 & 场景 › 创建自动化 › 创建新的自动化。
  • 2. 添加触发器 › Webhook。Home Assistant 会为你生成一个很长的随机 Webhook ID。
  • 3. 把它换成你认得出的名称，例如 avr-power-on、avr-movie-night。只要在你的 Home Assistant 上唯一，任何名称都可以。把它记下来，你要在 AVR Maestro 中输入同一个。
  • 4. 在 Webhook 的设置下，允许 POST。这是 AVR Maestro 发送的方式。仅限本地也没问题，应用就在你自己的网络上。
  • 5. 添加你希望它执行的任何操作，例如调暗灯光、关上窗帘、启动场景，然后保存该自动化。

在 AVR Maestro 中

  • 1. 设置 › 家庭自动化 › Webhook，然后点击添加第一个触发器；已有触发器后则点击 + 按钮。
  • 2. 触发事件：选择应由什么来触发它。选择输入源变更或场景已调用时，会多出第二个框用于进一步限定。
  • 3. 发送目的地：保持为 Home Assistant。地址已经知道了，因为你之前已在这个界面中完成了关联。
  • 4. Webhook ID：输入与 Home Assistant 中相同的 ID。其他内容不必匹配。下方应用会写明它将发送到的完整地址 Sends to http://your-ha:8123/api/webhook/avr-power-on，方便你在保存前核对。
  • 5. 保存。然后在列表中对该触发器点按测试。你的 Home Assistant 自动化应当立即运行。
走 Home Assistant 方案时，你永远不需要输入 URL。应用会根据你关联的 Home Assistant 构建它，并且每次触发器触发时都会重新查找该地址。把 Home Assistant 换到新端口、新主机名或 Nabu Casa 地址，你已创建的所有 Webhook 都会随之更新。无需重新同步，也没有按钮要按。
如果面板上显示尚未关联 Home Assistant，请先完成本页顶部的 Home Assistant 卡片。Webhook 方案需要一个地址作为基础。

发送到 Home Assistant 以外的地方

把发送目的地切换为其他，并将完整 URL 粘贴到 Webhook URL。任何能接收 POST 的东西都可以：Node-RED 流程、IFTTT 小程序、NAS 上的脚本、Hubitat Maker API 端点。这种方式会原样保存你输入的地址，所以如果目的地变了，你需要编辑触发器。

实际发送的内容

一个小型 JSON 正文。同一界面上的发送内容卡片会针对你选的触发器用通俗的语言说明，所以你无需猜测。下面是你的自动化会读取的字段名称：

触发器消息中的字段
接收机开机 / 关机event, timestamp
输入源变更…另外还有 source
场景已调用…另外还有 sceneId 和 sceneName

在 Home Assistant 自动化中，这些字段会以 {{ trigger.json.event }}、{{ trigger.json.source }} 等形式到达。你可以读取它们，也可以完全忽略，只对“已触发”这件事作出响应。大多数人选择后者。

如果你需要不同的格式，比如某个服务要求自己的格式，请打开该卡片下方的改为发送我自己的 JSON，在那里编写。它被折叠起来并标记为高级，是因为几乎没有人需要它，而不是因为不鼓励使用。

这个界面叫Webhook，因为它就是 Webhook。如果你要找的是在中枢上运行的自动化，那是上方的 Home Assistant 和 Hubitat 卡片：同步后的场景在那里是脚本，而不是这里的 Webhook。

Webhook 没有送达时

按值得检查的顺序排列，因为前两项几乎总是原因所在：

  • 先点按测试。它会向同一个地址发送与真实触发器相同的消息，并告诉你发生了以下三种情况中的哪一种：已送达、未送达，或因触发器自身的开关处于关闭而被跳过。如果测试能送达而真实事件不能，问题就出在触发器上，最常见的是输入源变更被限定在一个你实际上并没有切换到的输入源。
  • 检查 ID 是否完全一致。Home Assistant 的 Webhook ID 区分大小写，也不容许多余的空格。应用会在输入框下方显示它将发送到的完整地址，请与你自动化中的地址对比。
  • 检查自动化是否允许 POST。只允许 GET 的 Home Assistant Webhook 触发器，会悄无声息地忽略 AVR Maestro 发送的内容。
  • 检查触发器的开关是否已开启。列表中的每个触发器都有自己的开关，处于关闭状态的触发器会被跳过，而不是报告失败。
  • 触发器属于某一台接收机。你正在查看的列表，是当前所选接收机的列表。另一台接收机有它自己的列表，所以在这里创建的规则不会对另一个房间触发。
  • 应用必须在监视。察觉接收机发生变化的是 AVR Maestro，所以应用关闭、手机放在口袋里时，不会触发任何内容。这是本节开头所述的取舍，不是故障。
  • Webhook 属于家庭自动化的一部分。未解锁时，触发器可见但不会发送任何内容，而且测试会如实说明，而不是假装成功。
哪些付费，哪些不付费

家庭自动化是唯一的解锁项。AI 助手是免费的。

家庭自动化（专业版），包括 Home Assistant、Hubitat 和出站 Webhook，是一次性解锁。AVR Maestro 中的其他所有功能，包括设备端 AI 助手，都已包含在应用内。

语音控制是通过家庭自动化，经由你的中枢来控制接收机的。AVR Maestro 本身不运行语音识别。

常见问题

家庭自动化常见问题解答

语音控制需要保持手机开机吗？
不需要。AVR Maestro 会把你的场景编译为原生 Home Assistant 脚本。Home Assistant 直接通过本地网络与接收机通信，所以你的手机可以关机、休眠，甚至身在另一个国家。
哪些语音助手可以控制我的接收机？
你已经在用的任何一个。AVR Maestro 不会添加自己的语音层，它只是把脚本发布到 Home Assistant 或 Hubitat，再由你信任的这个中枢开放给 Alexa、Google Assistant 或 Siri 快捷指令。
AI 助手属于付费解锁内容吗？
不属于。设备端 AI 助手是免费的。家庭自动化，包括 Home Assistant、Hubitat 和出站 Webhook，是 AVR Maestro 中唯一的付费解锁项。
有任何内容会离开我的家庭网络吗？
控制不会。应用通过你自己的网络与接收机和中枢通信，任何内容都不会经过 MiyaraHub 的服务器。Webhook 会发往你指定的地址，这由你自己决定。
