詢問您的接收器

詢問助理，答案來自您的接收器

大多數助理對接收器只有一般性的了解，而這個助理了解的是您的接收器：它目前的音量、正在使用的喇叭預設、Dynamic EQ 是否開啟、此刻正在解碼什麼。它會讀取您自己的接收器並據此回答，使用的是在您裝置上執行的模型，而不是別處的某個服務。

位置

助理分頁

輸入問題，或按住麥克風說出來。不需要登入、不需要貼上金鑰，也不需要帳號。只要您的裝置能執行裝置端模型，開啟助理就能立刻使用。

用您自己的話提問都可以。「現在音量多大」、「我現在用什麼格式在看」、「載入的是哪個 Dirac 插槽」、「Dynamic EQ 有開嗎」，它會根據接收器實際回報的內容來理解您的意思，所以您不必知道設定的正式名稱。

它能告訴您什麼

應用程式從您的接收器讀取到的所有資訊，也就是本指南各畫面上的所有內容。這不是固定的清單：回報支援 IMAX 的機型會被問到 IMAX，不支援的機型則完全不會出現這個選項。

詢問內容它掌握的資訊
電源與音量開機或待機、dB 電平、靜音、ECO 模式，以及接收器本身的音量上限
訊源與音效目前選擇的輸入（以您取的名稱顯示）、音效模式，以及正在解碼的格式
校正Audyssey MultEQ、Dynamic EQ、Dynamic Volume、參考電平偏移、LFC，以及目前載入的 Dirac Live 插槽
喇叭配置、各聲道微調、重低音電平，以及已設定的重低音數量
視訊輸入與輸出的解析度及 HDR、畫面模式、視訊處理、輸入模式、HDMI 音訊輸出、自動音畫同步
分區各分區的電源、輸入、音量、聲道微調、睡眠計時器，以及 Smart Select / Quick Select 插槽
機身前面板亮度、自動待機、藍牙發射器，以及依編號顯示的每個觸發輸出
正在播放網路訊源上的曲目及其播放狀態
每個答案下方都會列出它讀取了什麼才得出答案。這一行是系統記錄的，不是由模型寫的，所以無法捏造，也是分辨真實答案與聽起來很有把握的錯誤答案的最快方法。

它能為您做什麼

要求它變更某項設定，它就會執行。差別只在於每個操作需要多少確認手續，而這樣的差異是刻意設計的。

要求會發生什麼事
開機或關機、靜音、取消靜音立即執行，然後告訴您它送出了什麼指令
調低音量立即執行。當有人想要小聲一點時，正是最不想被對話框打斷的時候
調高音量會先詢問。這是唯一最糟情況（喇叭單體損壞）無法由在場的人復原的操作
切換輸入會比對您自己的訊源清單，以您重新命名後的名稱為準。如果有兩個可能的符合項目，它會問您是哪一個

調整幅度由您決定。「調低 5 dB」就會調低 5 dB；只說「調小聲一點」而沒有數字，則只調一格，就和按一次按鈕一樣。它不會自行決定您沒說的數值。

目前尚不支援從這裡變更音效模式。您的接收器是依類別整理音效模式，並在目前的類別內選擇，因此不是只要送出單一名稱即可，請改用音效分頁來正確操作。

詢問意見

「有什麼校正建議嗎？」、「怎麼讓對白更清楚？」、「我該開啟 Dynamic EQ 嗎？」這類問題與查詢資料不同，助理的處理方式也不同。它會根據您的讀數進行推論，提出幾個具體的選項，每個都對應接收器實際擁有的設定，並說明它會優先嘗試哪一個。

不變的是數字的來源。它可以自由推論，但不能說出沒有提供給它的數字。如果您的讀數不足以支持某項建議，它會說明還需要看到什麼，而不是隨便猜測。

用說的，不用打字

按住麥克風按鈕並說話。它會把您說的內容填入輸入框，讓您在送出前先確認。

請注意：語言模型在您的裝置上執行，接收器也在您自己的網路中，因此您輸入的問題與得到的答案都會留在您的硬體上。語音轉文字由手機內建的辨識功能處理，在大多數手機上，音訊會傳送給平台供應商進行轉譯。這是作業系統的行為，而不是應用程式的行為，改用打字即可完全避免。
裝置需求

哪些裝置可以執行

助理會在您自己的裝置上執行語言模型。不需要帳號，不需要伺服器，也不需要登入，這同時意味著裝置上必須已有模型。這不是應用程式能代您安裝的，也是我們唯一無法繞過的需求。

平台需求
iPhone、iPad、MaciOS 26 或 macOS 26，且裝置支援 Apple Intelligence 並已開啟。如果未開啟，應用程式會告知您並引導至設定，而不是隱藏此功能。
Android透過 Google AICore 使用 Gemini Nano。應用程式透過 Google 的 ML Kit Prompt API 存取，而該 API 有自己的支援裝置清單，請見下方。
Windows、Linux沒有可執行的裝置端模型，因此不會顯示助理。應用程式的其他功能不受影響。

疑難排解

當它表示無法協助時

以下每一句話都刻意不同，因為每一種情況的解法也不同。

  • 「此裝置無法執行裝置端模型。」助理需要 iPhone、iPad 或 Mac 上的 Apple Intelligence，或 Android 上透過 Google AICore 執行的 Gemini Nano。許多其他方面效能很強的裝置並未涵蓋在內，包括部分新款平板，以及一些能為其他功能執行 Gemini Nano 的旗艦手機。請參閱上方的哪些裝置可以執行。這無法從應用程式中變更。
  • 模型需要下載。Android 會在第一次使用時於背景下載。這只需要一次，檔案很大，而且需要 Wi-Fi。
  • 「您的接收器具備該功能，但目前沒有可回報的內容。」該功能存在，只是目前閒置。在沒有任何播放時詢問正在播放什麼，就會得到這個回應，而不是宣稱您的接收器沒有 HEOS。
  • 「此接收器不會回報該項目。」這是針對您硬體的真實答案：機身沒有這項功能，應用程式也不會假裝有。
  • 某個子系統無法讀取。代表未知，而非不存在。它會如實告知，而不是把讀取失敗當成您沒有該功能。
  • 「我目前還無法從這裡變更這一項。」這是助理的限制，而不是接收器的限制，對應的畫面是可以變更的。
助理是免費的。居家自動化才是付費的部分，兩者各自獨立：向接收器提問並不需要進階版。
常見問題

助理常見問題解答

助理會把我的資料傳送到其他地方嗎？
語言模型在您的裝置上執行，而您的接收器位於您自己的網路中，因此您輸入的問題與其答案不會離開您的硬體。語音輸入是例外：將語音轉成文字是由手機自己的辨識器完成，在大多數手機上，這代表音訊會傳送到平台供應商進行轉錄。改用打字就能完全避免這一點。
為什麼助理說我的裝置無法執行它？
助理需要裝置端模型：iPhone、iPad 與 Mac 使用 Apple Intelligence，Android 則透過 Google AICore 使用 Gemini Nano。許多效能不錯的裝置並沒有這類模型。應用程式會明確告知目前處於哪種狀態，而不是直接隱藏此功能，讓您知道問題出在下載、設定還是硬體。
助理會在沒問過我的情況下就變更設定嗎？
電源、靜音、輸入切換與調低音量，它會直接執行，因為在場的人都能輕易復原這些操作。調高音量則一律會先詢問，因為這是唯一最糟情況可能損壞喇叭單體的操作。
為什麼它有時會說無法告訴我某些資訊？
因為它不會亂猜。它提供的每個數字都來自從您的接收器讀取的資料，所以如果沒有收到讀數，它會說明該子系統無法讀取，而不是編造一個看似合理的數字。聽起來正確卻是錯的答案，比沒有答案更糟。
