Home Assistant · Hubitat · Webhook

Home Assistant 與 Hubitat：您的場景，不需手機也能執行

將 AVR Maestro 連結至 Home Assistant 或 Hubitat，您建立的每個場景都會變成中樞上的原生腳本。此後由中樞直接在您自己的網路上與接收器通訊，所以即使手機關機、休眠或身在國外，「Alexa，電影之夜」依然有效。

為什麼不需要應用程式也能執行

大多數整合都讓您的手機充當中間人：手機聽到指令、手機送出指令，而自動化只有在手機清醒且連上網路時才能運作。

AVR Maestro 不這樣做。它會將您的場景編譯成存放在中樞上的腳本，再由中樞將指令送到接收器的區域網路 IP。同步完成後，應用程式的工作就結束了。

  • 本機優先：沒有任何內容經過 MiyaraHub 的伺服器。您的中樞與接收器直接彼此通訊。
  • 不依賴手機：場景一旦發布，不論建立它的手機有沒有安裝應用程式，都能執行。
  • 用您的助理，而不是我們的：Alexa、Google Assistant 與 Siri 捷徑，都是透過您信任的中樞來使用這些腳本。AVR Maestro 本身不加入任何語音層。

Home Assistant，從頭到尾

  • 1. 請先將您的接收器新增至 Home Assistant。設定 › 裝置 & 服務 › 新增整合 › Denon AVR（或 HEOS），然後輸入接收器的本機 IP。Home Assistant 會為它建立一個媒體播放器實體。
  • 2. 在 AVR Maestro 中開啟「設定 › 居家自動化」，並點選 Home Assistant 卡片。
  • 3. 輸入您的 Home Assistant 位址，可以是區域網路位址如 http://192.168.1.150:8123，或您的外部 Nabu Casa URL。
  • 4. 登入並授權。會開啟安全的應用程式內瀏覽器，顯示 Home Assistant 自己的登入頁面。您的憑證只會交給 Home Assistant，絕不會傳給我們。
  • 5. 它會自動找到您的接收器。應用程式會掃描您的媒體播放器實體，依型號、名稱與環繞能力評分，然後自動為您填入正確的實體。
  • 6. 同步。您的場景會被建置成腳本並上傳。之後編輯場景時，腳本會在背景自動更新，不需要記得按任何按鈕。
同步完成之後

打造一個值得一看的儀表板

Home Assistant 現在為接收器能接受的每項指令都提供了控制項，但對該怎麼排列完全沒有意見。儀表板範例就是一種附完整 YAML 的排列方式：成為使用中項目時會亮起的訊源與環繞磚、以真實 dB 顯示的音量、會讀取自己名稱的場景，以及一張誠實標示 Home Assistant 看得到與看不到什麼的地圖。

不只是場景

喇叭預設、Dirac 與 Audyssey 也包含在內

開啟同步進階控制項後，應用程式發布的腳本就遠不只您的場景：每個喇叭預設、每個 Dirac Live 濾波器槽位，以及每條 Audyssey 曲線都有。在 Cinema 30 上完整同步會產生七十多個腳本，所以儀表板按鈕或語音指令可以載入 Dirac 濾波器或切換房間曲線，就像叫出一個場景一樣。

不只寫入，也能讀取

Home Assistant 看得到目前啟用的是什麼

腳本只能執行，無法讀取，因此早期的儀表板雖然能切換 Audyssey 曲線或 Dirac 槽位，卻無法顯示目前是哪一個。應用程式已掌握的讀數，包括即時環繞模式、使用中的 Dirac 濾波器、喇叭預設、亮度和其他數十項，現在都會以屬性的形式發布在接收器的狀態感測器上，讓磚能為實際運作中的設定亮起。

每個房間

您的其他分區，同一個儀表板就能控制

分區 2 與分區 3 的電源、音量與靜音會各自發布為獨立腳本，因此露台或第二個房間，就能像主分區一直以來那樣回應儀表板或語音助理。只有接收器實際回報的分區才會有按鈕，所以雙分區的接收器永遠不會多出分區 3。

如果您曾用舊版同步過

您的腳本 ID 會變動一次

腳本過去是以場景與接收器命名，因此重新命名其中任何一個，都會留下舊腳本，並悄悄產生第二個。現在改以場景與接收器的 MAC 位址命名，這樣重新命名時才會更新同一個腳本，而不是產生分支。

這項變更之後的第一次同步，會以新腳本取代舊腳本。任何建立在舊 ID 上的內容都需要重新指向一次，例如儀表板按鈕、自動化或語音別名。請在 Home Assistant 中開啟該腳本，找出它的新實體 ID。

實體現在也會依接收器命名，例如 cinema30，而不是三十二個字元的機器識別碼，所以清單清楚易讀，自動完成也找得到它們。早期版本的 ID 仍可繼續使用。

Hubitat

Hubitat 透過其 Maker API 支援，並在應用程式中標示為 BETA，原因是它比 Home Assistant 路線更新，而不是因為尚未完成。

  • 中樞 IP：您的 Hubitat 在區域網路上的位址。
  • Maker API App ID：Maker API 應用程式自己網址中的那組數字。
  • 存取權杖：啟用 Maker API 時簽發。

請先在中樞上啟用 Maker API（Apps › Add Built-In App › Maker API），它就會給您這三項資料。貼上之後，AVR Maestro 會探索您的接收器，將您的場景發布為指令序列，並把即時狀態推回去，讓 Hubitat 儀表板反映接收器實際的狀況，而不是它最後一次被告知的內容。

Webhook

Home Assistant 與 Hubitat 是將指令送到接收器。Webhook 則是反方向：當接收器有動作時，通知其他任何東西。開啟接收器，AVR Maestro 就會向您指定的位址送出一則小訊息，這則訊息就是 Webhook。

這是唯一不獨立於手機的部分。您同步的場景會變成中樞上的腳本，不論應用程式在不在附近都能執行。Webhook 則不同：觀察接收器的是 AVR Maestro，所以只有在應用程式於能連到接收器的裝置上開啟時，觸發器才會觸發。如果您希望在沒有任何東西運作的情況下也能觸發，請改在中樞上圍繞接收器實體來建立。

四種觸發器

觸發事件觸發時機可縮小範圍至
接收器電源開啟接收器離開待機-
接收器電源關閉接收器進入待機-
使用中輸入已變更已選訊源改變單一輸入，位於僅針對輸入訊源觸發下
已叫出場景套用了某個場景單一場景，位於選擇場景下

縮小範圍才能讓它們有用而不吵雜。對每個輸入都啟用「使用中輸入已變更」就像消防水管；同一個觸發器若只鎖定投影機所在的那個輸入，就是一個電燈開關。

輸入清單是您自己的接收器所回報的，因此已反映您重新命名或隱藏的任何訊源。場景清單則是您自己的場景。

逐步設定一個

這是 Home Assistant 路線，也是大多數人想要的。請先完成 Home Assistant 那一半，因為應用程式需要有指向的目標。

在 Home Assistant 中

  • 1. 設定 › 自動化 & 場景 › 建立自動化 › 建立新的自動化。
  • 2. 新增觸發條件 › Webhook。Home Assistant 會為您產生一組冗長的隨機 Webhook ID。
  • 3. 換成您認得出來的名稱，例如 avr-power-on、avr-movie-night。只要在您的 Home Assistant 上是唯一的，任何名稱都可以。請記下來，您要在 AVR Maestro 中輸入同一個。
  • 4. 在 Webhook 的設定中，允許 POST。這是 AVR Maestro 送出的方式。僅限本機即可，因為應用程式就在您自己的網路上。
  • 5. 加入您希望它執行的動作，例如調暗燈光、關上窗簾、啟動場景，然後儲存自動化。

在 AVR Maestro 中

  • 1. 設定 › 居家自動化 › Webhook，然後點新增第一個觸發器，或在已有觸發器時點 + 按鈕。
  • 2. 觸發事件：選擇要由什麼來觸發。選擇使用中輸入已變更或已叫出場景時，會多出第二個方塊供您縮小範圍。
  • 3. 傳送目的地：保持在 Home Assistant。位址已經知道，因為您稍早已在這個畫面連結過。
  • 4. Webhook ID：輸入與您在 Home Assistant 中使用的相同 ID。其他都不需要相符。下方應用程式會列出它將要送出的完整位址：Sends to http://your-ha:8123/api/webhook/avr-power-on，讓您在儲存前檢查。
  • 5. 儲存。然後在清單中按下該觸發器的測試。您的 Home Assistant 自動化應該會立即執行。
Home Assistant 路線不需要您輸入任何 URL。應用程式會根據您連結的 Home Assistant 建立它，並且每次觸發器觸發時都會重新查詢該位址。將 Home Assistant 換到新的連接埠、新的主機名稱或 Nabu Casa 位址，您已建立的每個 Webhook 都會跟著更新。不需要重新同步，也不用按任何按鈕。
如果面板顯示尚未連結 Home Assistant，請先完成本頁上方的 Home Assistant 卡片。Webhook 路線需要有位址才能建立。

傳送到 Home Assistant 以外的地方

將傳送目的地切換為其他，並在 Webhook URL 貼上完整的 URL。任何接受 POST 的東西都可以，例如 Node-RED 流程、IFTTT 小程式、NAS 上的腳本，或 Hubitat Maker API 端點。這條路線會原封不動地儲存您輸入的位址，因此目的地移動時，您需要編輯該觸發器。

實際送出的內容

一個小型 JSON 內容。同一畫面上的傳送內容卡片，會用白話描述您所選觸發器的內容，所以您不必猜測；以下是您的自動化會讀取的欄位名稱：

觸發器訊息中的欄位
接收器電源開啟 / 關閉event, timestamp
使用中輸入已變更...另加 source
已叫出場景...另加 sceneId 和 sceneName

在 Home Assistant 自動化中，這些會以 {{ trigger.json.event }}、{{ trigger.json.source }} 等形式送達。您可以讀取它們，也可以完全忽略，只針對它已觸發這件事採取行動。大多數人都選後者。

如果您需要不同的格式（例如某個服務要求自己的格式），請在該卡片下方開啟改為傳送我自己的 JSON並在那裡撰寫。它是收合起來並標為進階的，因為幾乎沒有人需要，而不是因為不鼓勵使用。

這個畫面叫做 Webhook，因為它們就是 Webhook。如果您要找的是在中樞上執行的自動化，那是上方的 Home Assistant 與 Hubitat 卡片：同步的場景在那裡會變成腳本，而不是這裡的 Webhook。

Webhook 沒有送達時

請依序檢查，因為前兩項幾乎都是原因所在：

  • 先按測試。它會把與真實觸發器相同的訊息送到相同的位址，並告訴您發生了以下三種情況的哪一種：已送達、未送達，或因為該觸發器自己的開關關閉而略過。如果測試成功送達而實際事件卻沒有，問題就出在觸發器，最常見的是使用中輸入已變更被縮小到一個您實際上並不會切換過去的輸入。
  • 檢查 ID 是否完全相符。Home Assistant 的 Webhook ID 區分大小寫，也容不下多餘的空格。應用程式會在欄位下方列出它將要送出的完整位址，請與您自動化中的位址比對。
  • 檢查自動化是否允許 POST。只允許 GET 的 Home Assistant Webhook 觸發器，會悄悄忽略 AVR Maestro 送出的內容。
  • 檢查觸發器的開關是否已開啟。清單中每個觸發器都有自己的切換開關，已關閉的觸發器會被略過，而不是失敗。
  • 觸發器屬於單一接收器。您目前看到的清單，是目前所選接收器的清單。另一台接收器有自己的清單，所以在這裡建立的規則不會對另一個房間觸發。
  • 應用程式必須在監看。是 AVR Maestro 注意到接收器改變了，所以口袋裡的手機若沒有開啟應用程式，就不會觸發任何東西。這是本節開頭所說明的取捨，不是故障。
  • Webhook 屬於居家自動化的一部分。未解鎖時，觸發器看得到但不會送出任何東西，而且測試會直接說明，而不是假裝成功。
哪些要付費，哪些不用

居家自動化是唯一的解鎖項目。AI 助理是免費的。

居家自動化（Pro），包含 Home Assistant、Hubitat 與對外 Webhook，是一次性解鎖。AVR Maestro 中的其他一切，包括裝置端 AI 助理，都已包含在應用程式內。

語音控制是透過居家自動化，經由您的中樞來控制接收器。AVR Maestro 本身不執行語音辨識。

常見問題

居家自動化常見問題

語音控制時，我的手機需要開著嗎？
不需要。AVR Maestro 會將您的場景編譯成原生的 Home Assistant 腳本。Home Assistant 直接透過您的區域網路與接收器通訊，所以您的手機可以關機、休眠，甚至身在另一個國家。
哪些語音助理可以控制我的接收器？
您原本在用的那個都可以。AVR Maestro 不會自行加入語音層，它只是把腳本發布到 Home Assistant 或 Hubitat，再由您信任的中樞開放給 Alexa、Google Assistant 或 Siri 捷徑使用。
AI 助理屬於付費解鎖的一部分嗎？
不是。裝置端 AI 助理是免費的。居家自動化（Home Assistant、Hubitat 與對外 Webhook）是 AVR Maestro 中唯一的付費解鎖項目。
有任何資料會離開我的家用網路嗎？
控制用途不會。應用程式透過您自己的網路與接收器及中樞通訊，沒有任何內容經過 MiyaraHub 的伺服器。Webhook 會送到您指定的地方，這由您決定。
