Home Assistant ו-Hubitat: הסצנות שלכם, רצות בלי הטלפון

קשרו את AVR Maestro ל-Home Assistant או ל-Hubitat וכל סצנה שבניתם הופכת לסקריפט מקורי ברכזת שלכם. מאותו רגע הרכזת מדברת עם המקלט ישירות, ברשת שלכם - כך ש"Alexa, movie night" עובד כשהטלפון כבוי, במצב שינה, או במדינה אחרת.

למה זה רץ בלי האפליקציה

רוב האינטגרציות הופכות את הטלפון לתיווך: הטלפון שומע את הפקודה, הטלפון שולח אותה, והאוטומציה עובדת רק כשהטלפון ער ומחובר לרשת.

AVR Maestro לא עושה את זה. הוא מהדר את הסצנות שלכם לסקריפטים שחיים ברכזת, והרכזת שולחת את הפקודות לכתובת ה-IP המקומית של המקלט. תפקיד האפליקציה נגמר כשהסנכרון מסתיים.

  • מקומי קודם כול: שום דבר לא עובר דרך שרת של MiyaraHub. הרכזת והמקלט שלכם מדברים אחד עם השני.
  • בלי תלות בטלפון: ברגע שסצנה פורסמה היא רצה בין אם האפליקציה מותקנת בטלפון שיצר אותה ובין אם לא.
  • העוזר שלכם, לא שלנו: Alexa, Google Assistant ו-Siri Shortcuts כולם מגיעים לסקריפטים האלה דרך הרכזת שכבר סומכים עליה. AVR Maestro לא מוסיף שכבת קול משלו.

Home Assistant, מההתחלה ועד הסוף

  • 1. הוסיפו קודם את המקלט שלכם ל-Home Assistant. הגדרות › מכשירים & שירותים › הוספת אינטגרציה › Denon AVR (או HEOS), ולאחר מכן כתובת ה-IP המקומית של המקלט. Home Assistant יוצר עבורו ישות נגן מדיה.
  • 2. פתחו את הגדרות › אוטומציה ביתית (Pro) ב-AVR Maestro והקישו על כרטיס Home Assistant.
  • 3. הזינו את כתובת Home Assistant שלכם - כתובת מקומית כמו http://192.168.1.150:8123, או כתובת Nabu Casa החיצונית שלכם.
  • 4. התחברו ואשרו. דפדפן מאובטח בתוך האפליקציה פותח את מסך ההתחברות של Home Assistant עצמו. פרטי ההתחברות שלכם הולכים ל-Home Assistant, אף פעם לא אלינו.
  • 5. הוא מוצא את המקלט שלכם בעצמו. האפליקציה סורקת את ישויות נגן המדיה שלכם ומדרגת אותן לפי דגם, שם ויכולת סראונד, ואז ממלאת בשבילכם את הישות הנכונה.
  • 6. סנכרון. הסצנות שלכם נבנות לסקריפטים ומועלות. אחרי זה, עריכת סצנה מעדכנת את הסקריפט שלה ברקע - אין כפתור לזכור.
אחרי שזה מסונכרן

בנו לוח בקרה ששווה להסתכל עליו

עכשיו יש ל-Home Assistant פקד לכל דבר שאפשר להגיד למקלט שלכם לעשות, ובכלל אין לו דעה איך לסדר אותם. דוגמת לוח הבקרה היא סידור אחד עם ה-YAML המלא: אריחי מקור וסראונד שנדלקים כשהם הפעילים, עוצמת קול ב-dB אמיתיים, הסצנות שלכם שקוראות את השמות של עצמן, ומפה כנה של מה ש-Home Assistant יכול ולא יכול לראות.

לא רק סצנות

גם פריסטים לרמקולים, Dirac ו-Audyssey

הפעילו את סנכרון פקדים מתקדמים והאפליקציה מפרסמת סקריפט להרבה יותר מהסצנות שלכם: כל פריסט רמקולים, כל חריץ מסנן של Dirac Live, כל עקומת Audyssey. סנכרון מלא ב-Cinema 30 מגיע ליותר משבעים סקריפטים, כך שכפתור בלוח הבקרה או פקודה קולית יכולים לטעון מסנן Dirac או להחליף את עקומת החדר באותו אופן שבו הם משחזרים סצנה.

הוא גם קורא, לא רק כותב

Home Assistant יכול לראות מה פעיל

סקריפט אפשר להריץ אבל אי אפשר לקרוא, ולכן לוחות בקרה מוקדמים יכלו להחליף את עקומת Audyssey או את חריץ Dirac בלי שום דרך להראות איזה מהם דלוק. הקריאות שהאפליקציה כבר מחזיקה - מצב הסראונד החי, מסנן Dirac הפעיל, פריסט הרמקולים, העמעום ועוד עשרות - מתפרסמות עכשיו כמאפיינים בחיישן הסטטוס של המקלט, כך שאריח יכול להידלק עבור ההגדרה שבאמת רצה.

מצבי סאונד כסקריפטים

ייצוא מצבי סאונד (REST)

בקטע Home Assistant, ייצוא מצבי סאונד (REST) פותח את סקריפט מתקדם (REST): סקריפט Home Assistant אחד לכל מצב סאונד שהמקלט שלכם מפרט, כך שכפתור בלוח הבקרה או אוטומציה יכולים לבחור מצב סראונד ישירות. האפליקציה קוראת את הרשימה הזו מהמקלט, לכן הדליקו את המקלט ופתחו פעם אחת את לשונית הסאונד קודם; עד אז היא מבקשת זאת מכם, במקום לייצא רשימה ריקה.

כל חדר

האזורים האחרים שלכם, מאותו לוח בקרה

הפעלה, עוצמת קול והשתקה של אזור 2 ואזור 3 מתפרסמים כסקריפטים משלהם, כך שמרפסת או חדר שני עונים ללוח בקרה או לעוזר קולי כמו שהאזור הראשי תמיד ענה. רק האזורים שהמקלט שלכם באמת מדווח עליהם מקבלים כפתורים, כך שמקלט עם שני אזורים לעולם לא מצמיח אזור 3.

אם סנכרנתם עם גרסה ישנה

מזהי הסקריפטים שלכם משתנים פעם אחת

פעם סקריפטים נקראו לפי הסצנה וגם לפי המקלט, ולכן שינוי שם של אחד מהם השאיר את הסקריפט הישן מאחור ויצר בשקט סקריפט שני. עכשיו הם נקראים לפי הסצנה וכתובת ה-MAC של המקלט, וזה מה שגורם לשינוי שם לעדכן את אותו סקריפט ולא ליצור עותק נוסף.

הסנכרון הראשון אחרי השינוי הזה מחליף את הסקריפטים הישנים בחדשים. כל מה שבניתם על המזהים הישנים צריך להצביע מחדש פעם אחת - כפתור בלוח בקרה, אוטומציה, כינוי קולי. פתחו את הסקריפט ב-Home Assistant כדי למצוא את מזהה הישות החדש שלו.

גם הישויות נקראות עכשיו לפי המקלט - cinema30 ולא שלושים ושניים תווים של מזהה מכונה - כך שהרשימה קריאה והשלמה אוטומטית מוצאת אותן. מזהים מגרסאות קודמות ממשיכים לעבוד.

Hubitat

Hubitat נתמך דרך ה-Maker API שלו, ומסומן BETA באפליקציה כי הוא חדש יותר מהנתיב של Home Assistant, לא כי הוא לא גמור.

  • Hub IP - הכתובת של ה-Hubitat שלכם ברשת המקומית.
  • Maker API App ID - המספר שבכתובת ה-URL של אפליקציית Maker API עצמה.
  • Access Token - מונפק על ידי Maker API כשמפעילים אותו.

הפעילו קודם את Maker API ברכזת (Apps › Add Built-In App › Maker API) והוא ימסור לכם את שלושתם. הדביקו אותם ו-AVR Maestro מגלה את המקלט שלכם, מפרסם את הסצנות שלכם כרצפי פקודות, ודוחף חזרה מצב חי, כך שלוח בקרה של Hubitat משקף מה שהמקלט באמת עושה ולא מה שנאמר לו בפעם האחרונה.

Webhooks

Home Assistant ו-Hubitat שולחים פקודות אל המקלט. Webhooks הולכים לכיוון ההפוך: כשהמקלט עושה משהו, לספר על זה לכל דבר אחר. מדליקים את המקלט ו-AVR Maestro שולח הודעה קטנה לכתובת שבחרתם - ההודעה הזו היא ה-webhook.

זה החלק היחיד שאינו בלתי תלוי בטלפון. הסצנות המסונכרנות שלכם הופכות לסקריפטים ברכזת ורצות בין אם האפליקציה קרובה ובין אם לא. Webhooks שונים: AVR Maestro הוא זה שמשגיח על המקלט, ולכן טריגר יורה כשהאפליקציה פתוחה במכשיר שרואה אותו. אם רוצים שמשהו יירה כשכלום לא רץ, בנו אותו ברכזת סביב ישות המקלט.

ארבעת הטריגרים

אירוע טריגריורה כאשראפשר לצמצם ל
Receiver Power ONהמקלט יוצא ממצב המתנה-
Receiver Power OFFהמקלט נכנס למצב המתנה-
Active Input Changedהמקור הנבחר משתנהקלט אחד, תחת Only trigger for input source
Scene Recalledסצנה מוחלתסצנה אחת, תחת Select Scene

הצמצום הוא מה שהופך אותם לשימושיים ולא רועשים. "Active Input Changed" על כל קלט הוא צינור כיבוי אש; אותו טריגר שננעץ על הקלט האחד שאליו מחובר המקרן הוא מתג אור.

רשימת הקלטים היא זו שהמקלט שלכם מדווח, ולכן היא כבר משקפת כל מקור ששיניתם לו שם או הסתרתם. רשימת הסצנות היא הסצנות שלכם.

הגדרת טריגר, צעד אחר צעד

זה הנתיב של Home Assistant, זה שרוב האנשים רוצים. עשו קודם את החצי של Home Assistant - לאפליקציה צריך להיות משהו להצביע עליו.

ב-Home Assistant

  • 1. Settings › Automations & Scenes › Create Automation › Create new automation.
  • 2. Add Trigger › Webhook. Home Assistant מייצר עבורכם Webhook ID אקראי וארוך.
  • 3. החליפו אותו במשהו שתזהו - avr-power-on, avr-movie-night. כל שם עובד כל עוד הוא ייחודי ב-Home Assistant שלכם. רשמו אותו; תקלידו את אותו שם ב-AVR Maestro.
  • 4. בהגדרות ה-webhook, אפשרו POST. זה מה ש-AVR Maestro שולח. מקומי בלבד זה בסדר - האפליקציה ברשת שלכם.
  • 5. הוסיפו מה שתרצו שיקרה - עמעום אורות, סגירת תריסים, הפעלת סצנה - ושמרו את האוטומציה.

ב-AVR Maestro

  • 1. הגדרות › אוטומציה ביתית (Pro) › Webhooks, ואז הוספת הטריגר הראשון - או כפתור + כשכבר יש לכם אחד.
  • 2. Trigger Event - בחרו מה אמור להפעיל אותו. בחירה ב-Active Input Changed או ב-Scene Recalled מוסיפה תיבה שנייה לצמצום.
  • 3. Where to send it - השאירו על Home Assistant. הכתובת כבר ידועה, כי קישרתם אותו קודם באותו מסך.
  • 4. Webhook ID - הקלידו את אותו מזהה שהשתמשתם בו ב-Home Assistant. שום דבר אחר לא חייב להתאים. מתחת, האפליקציה כותבת את הכתובת המדויקת שאליה היא תשלח - Sends to http://your-ha:8123/api/webhook/avr-power-on - כדי שתוכלו לבדוק אותה לפני השמירה.
  • 5. שמרו. ואז לחצו על Test בטריגר שברשימה. האוטומציה שלכם ב-Home Assistant אמורה לרוץ מיד.
אף פעם לא מקלידים URL בנתיב של Home Assistant. האפליקציה בונה אותו מה-Home Assistant שקישרתם, והיא מחפשת את הכתובת הזו בכל פעם שטריגר יורה. מעבירים את Home Assistant לפורט חדש, לשם מארח חדש או לכתובת Nabu Casa, וכל webhook שכבר יצרתם עוקב אחריו. אין מה לסנכרן מחדש ואין כפתור ללחוץ עליו.
אם הגיליון אומר Home Assistant is not linked yet, עשו קודם את כרטיס Home Assistant בראש העמוד הזה. נתיב ה-webhook צריך כתובת לבנות עליה.

שליחה למקום שאינו Home Assistant

העבירו את Where to send it ל-Other והדביקו URL מלא ב-Webhook URL. כל דבר שמקבל POST עובד - זרימת Node-RED, אפלט IFTTT, סקריפט ב-NAS, נקודת קצה של Hubitat Maker API. הנתיב הזה שומר את הכתובת בדיוק כפי שהקלדתם, ולכן אם היעד עובר, עורכים את הטריגר.

מה בעצם נשלח

גוף JSON קטן. הכרטיס What it sends באותו מסך אומר אותו בשפה פשוטה עבור הטריגר שבחרתם, כך שאין צורך לנחש - ואלה שמות השדות שהאוטומציה שלכם קוראת:

טריגרשדות בהודעה
Receiver Power ON / OFFevent, timestamp
Active Input Changed...ועוד source
Scene Recalled...ועוד sceneId ו-sceneName

באוטומציה של Home Assistant אלה מגיעים כ-{{ trigger.json.event }}, {{ trigger.json.source }} וכן הלאה. אפשר לקרוא אותם, או להתעלם מהם לגמרי ולפעול רק על עצם העובדה שזה ירה. רוב האנשים עושים את השני.

אם אתם צריכים צורה אחרת - שירות שמצפה לפורמט משלו - פתחו את Send my own JSON instead מתחת לכרטיס הזה וכתבו אותה שם. הוא מקופל ומסומן Advanced כי כמעט אף אחד לא צריך אותו, לא כי לא מעודדים אותו.

המסך נקרא Webhooks כי זה מה שהם. אם אתם מחפשים את האוטומציות שרצות על הרכזת שלכם, אלה כרטיסי Home Assistant ו-Hubitat למעלה - סצנה מסונכרנת הופכת שם לסקריפט, לא ל-webhook כאן.

כש-webhook לא מגיע

לפי הסדר ששווה לבדוק, כי שני הראשונים כמעט תמיד הסיבה:

  • לחצו קודם על Test. הוא שולח את אותה הודעה שהטריגר האמיתי שולח, לאותה כתובת, ואומר לכם איזה משלושה דברים קרה: נשלח, לא נשלח, או דולג כי המתג של הטריגר עצמו כבוי. אם Test מגיע והאירוע האמיתי לא, הבעיה בטריגר - לרוב Active Input Changed שצומצם לקלט שאתם בעצם לא עוברים אליו.
  • בדקו שהמזהה תואם בדיוק. מזהי webhook של Home Assistant רגישים לאותיות גדולות וקטנות ולא סובלים רווח תועה. האפליקציה מדפיסה את הכתובת המלאה שאליה תשלח מתחת לשדה - השוו אותה לזו שבאוטומציה שלכם.
  • בדקו שהאוטומציה מאפשרת POST. טריגר webhook של Home Assistant שמאפשר רק GET מתעלם בשקט ממה ש-AVR Maestro שולח.
  • בדקו שמתג הטריגר דלוק. לכל אחד יש מתג משלו ברשימה, וטריגר כבוי מדולג ולא נכשל.
  • טריגרים שייכים למקלט אחד. הרשימה שאתם מסתכלים עליה היא הרשימה של המקלט שנבחר כרגע. למקלט אחר יש רשימה משלו, ולכן כלל שנוצר כאן לא יורה עבור חדר אחר.
  • האפליקציה צריכה להשגיח. AVR Maestro הוא זה שמבחין שהמקלט השתנה, ולכן שום דבר לא יורה מטלפון בכיס כשהאפליקציה סגורה. זו הפשרה שתוארה בראש המדור הזה, לא תקלה.
  • Webhooks הם חלק מאוטומציה ביתית. בלי הפתיחה הזו הטריגרים נראים אבל שום דבר לא נשלח, ו-Test אומר את זה ולא מעמיד פנים שזה עבד.
מה בתשלום ומה לא

אוטומציה ביתית היא הפתיחה היחידה. העוזר החכם חינם.
